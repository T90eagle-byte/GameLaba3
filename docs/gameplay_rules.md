# Gameplay rules

## Цель игры

Игрок управляет лабораторией и выводит существ с нужными свойствами. Основной цикл: выбрать родителей, провести скрещивание или мутагенный эксперимент, получить потомка, проверить выполнение заданий и улучшить лабораторию.

## Старт новой лаборатории

По ЛР2 процедура `start_new_lab` должна:

- создать лабораторию текущего пользователя;
- выдать начальный кошелек `1000`;
- установить рейтинг `0`;
- сгенерировать стартовых существ;
- выдать 3 стартовых задания;
- обновить счетчики лаборатории.

Стартовая коллекция по ЛР2:

- 6 биологических типов;
- по 5 особей каждого типа;
- всего 30 стартовых существ.

Для MVP принято использовать именно 6 типов из ЛР2. Упоминание 5 базовых видов в ЛР1 рассматривается как минимальный уровень требований, а не как ограничение текущей реализации.

Типы существ из ЛР2:

- хрящевые рыбы;
- костные рыбы;
- ракообразные;
- моллюски;
- черепахи;
- млекопитающие.

## Гены и аллели

Каждый признак задается геном. У существа по каждому гену хранится пара аллелей:

- `allele1_id`;
- `allele2_id`.

Гены бывают:

- универсальные, если `species_type = 0`;
- привязанные к типу существа, если `species_type` от 1 до 6.

Для сцепленного наследования у генов используется поле `linkage_group`. Если оно NULL, ген наследуется независимо; если указано значение группы, гены этой группы передаются совместно.

Типы доминирования:

- `FULL` - полное доминирование;
- `INCOMPLETE` - неполное доминирование;
- `CODOMINANT` - кодоминирование.

## Фенотип

Фенотип вычисляется в PL/SQL функцией `get_phenotype`.

Правила из ЛР2:

- если доминантность первого аллеля выше, проявляется первый аллель;
- если доминантность второго аллеля выше, проявляется второй аллель;
- если доминантности равны и тип `INCOMPLETE`, берется среднее числовое значение признака;
- если доминантности равны и тип `CODOMINANT`, отображаются оба признака;
- если доминантности равны и тип `FULL`, проявляется обычное значение признака.

Результат должен сохраняться в записи существа и возвращаться как текстовое описание для GUI.

В `creatures` хранятся только часто отображаемые фенотипические поля, например цвет, размер, наличие крыльев и тип питания. Полный фенотип строится функцией `get_phenotype`, чтобы Python не дублировал генетическую логику.

## Скрещивание

Скрещивание выполняется процедурой `crossbreed`.

Игрок выбирает двух родителей из своей лаборатории. PL/SQL:

- создает запись потомка;
- формирует генотип потомка;
- для независимых генов выбирает по одному аллелю от каждого родителя с вероятностью 50/50;
- для сцепленных генов передает целый набор аллелей одной группы сцепления;
- записывает эксперимент типа `CROSS`;
- пересчитывает фенотип потомка;
- проверяет, не выполнены ли задания.

Python показывает результат, но не рассчитывает его.

## Решетка Пеннета

Функция `calculate_punnett_probabilities` рассчитывает вероятности генотипов потомка для одного гена:

- берутся два аллеля первого родителя;
- берутся два аллеля второго родителя;
- строятся 4 комбинации;
- одинаковые генотипы группируются;
- возвращается курсор с вероятностями.

GUI может использовать это как экран прогнозирования перед скрещиванием.

## Мутации

Мутация - покупаемое изменение генотипа.

Игровой поток:

1. GUI получает список мутаций через `show_mutation_shop`.
2. Игрок покупает мутацию через `buy_mutation`.
3. PL/SQL проверяет кошелек, списывает стоимость и увеличивает запас в `lab_mutations`.
4. Игрок применяет мутацию через `apply_mutation`.
5. PL/SQL меняет генотип, записывает эксперимент `MUTATION`, уменьшает запас мутации и пересчитывает фенотип.

## Мутагены

Мутагены - экспериментальное воздействие на существо:

- радиация - случайное изменение;
- химикаты - изменение на близкий по типу вариант.

Процедура `apply_mutagen` выбирает ген, меняет один из аллелей и записывает эксперимент типа `MUTAGEN`.

## Главный эксперимент

`make_experiment` объединяет скрещивание и опциональное применение мутации:

1. вызывает `crossbreed`;
2. если передана мутация, проверяет ее наличие;
3. применяет `apply_mutation` к потомку;
4. возвращает `offspring_id`.

## Задания

Задание описывает набор требуемых признаков. В ЛР2 требования представлены через `task_markers`: каждый маркер указывает аллель, который должен присутствовать у существа.

Проверка:

- `check_task` получает лабораторию, задание и существо;
- выбирает все требуемые аллели задания;
- проверяет, что каждый из них есть в генотипе существа;
- возвращает `1`, если все требования выполнены, иначе `0`.

Завершение:

- `complete_task` переводит задание в `COMPLETED`;
- начисляет монеты;
- увеличивает рейтинг;
- обновляет статистику лаборатории;
- формирует уведомление для игрока.

## GUI-сценарии из PDF

Главное окно:

- создать новую лабораторию;
- загрузить сохраненную лабораторию;
- посмотреть краткую статистику;
- выйти из игры.

Коллекция:

- таблица или карточки существ;
- имя, тип, фенотип, поколение или идентификатор;
- просмотр генотипа выбранного существа.

Скрещивание:

- выбор двух родителей из коллекции;
- отображение генотипа и фенотипа родителей;
- выбор мутагенного воздействия;
- кнопка запуска;
- отображение потомка.

Задания:

- список заданий и статусов;
- выбор существа для проверки;
- показ результата и недостающих признаков.

Мутагенные эксперименты:

- выбор существа;
- выбор мутагена;
- подтверждение действия;
- показ измененного существа и измененного гена.

## Правило разделения ответственности

GUI может помогать игроку выбирать действия и отображать результаты. Все решения о том, что произошло в игре, принимает Oracle PL/SQL.

Python-клиент не использует `dbms_output`. Все игровые экраны должны получать данные через OUT-параметры, `sys_refcursor` или функции с простыми типами.
