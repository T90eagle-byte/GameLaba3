# Правила игры «БиоСборка»

Все игровые решения выполняет Oracle package `pkg_genetics_game`. Клиенты
показывают данные package cursors и вызывают его API, не рассчитывая
наследование, Монеты, рейтинг или выполнение Заданий.

Новые SQL/PLSQL изменения статически проверены на совместимость с Oracle 12.2.
Runtime validation на Oracle 12.2 должна быть выполнена на университетском
стенде.

## Совместимость v1

Исторические лаборатории остаются на `genetics_version=1`. Их legacy genes,
фенотипы и marker-based Задания сохранены без конвертации.

В v1 условие задания — носительство аллеля: каждый marker должен находиться в
одной из двух позиций соответствующего гена. Поэтому носитель рецессивного
аллеля может выполнить Задание, даже если этот признак не выражен внешне.

## Генетическая модель v3

Новые лаборатории используют `genetics_version=3` и 19 канонических генов:
`nutrition_type` плюс 18 морфологических traits. Морфология включает форму,
пропорции, размер, покров, окрас, рот, морду, глаза, передние и задние
конечности, хвост и спинную часть.

Архетип — только стартовый шаблон существа. После скрещивания, мутагена или
гибридизации внешний вид определяется сохранённым генотипом. Выраженный
фенотип вычисляется Oracle по правилам наследования и отображается renderer'ом.

v3-Задания проверяют выраженный фенотип, поэтому формулировки на странице
«Задания» говорят о видимом результате, а не о внутренних ID аллелей.

## Скрещивание и preview

- Обычное скрещивание доступно двум существам одного обычного вида.
- `preview_offspring_options` показывает до трёх случайных разных примеров
  возможного потомства. Это stateless preview, без создания существ и без
  фиктивной вероятности полного генотипа.
- `calculate_punnett_probabilities` применим к отдельному гену; его результат
  не является вероятностью конкретного полного потомка.
- «Скрещивание + мутаген» (`CROSSBREED_MUTAGEN`) создаёт один итоговый
  организм и одну логическую запись истории.

## Мутации и мутагены

Направленная мутация доступна только при наличии совместимого правила
соответствующей генетической модели. В текущем production-каталоге v3 нет
направленного morphology content; это осознанно отложенная часть контента, а
не ошибка применения.

Мутагены доступны через package:

- «Облучение» (`RADIATION`) — рискованная операция;
- «Химический мутаген» (`CHEMICAL`) — отдельный контролируемый режим.

Они создают результат и историю эксперимента по правилам Oracle. Клиент после
операции показывает фактически изменившиеся признаки, если package-данные
позволяют сравнить их состояние.

## Гибридизация

«Гибридизация» доступна в v3 для двух разных обычных видов и использует
«Облучение». Результат имеет `species_type=7`, не имеет архетипа и содержит
ровно 19 канонических генов. Гибрид не может участвовать в обычном
скрещивании или новой гибридизации, но может получать мутации и мутагены.

Гибридизация уменьшает рейтинг на 50, но рейтинг не становится отрицательным:
фактический delta ограничивается нулём и записывается в историю.

## Монеты, рейтинг и Задания

`labs.wallet` хранит Монеты, `labs.rating` — рейтинг. `rating_events`
объясняет награды, покупки и последствия экспериментов. Значения и reward
balance рассчитываются в Oracle.

Задания назначаются лаборатории и завершаются package API ровно один раз.
История экспериментов и рейтинг-событий сохраняются в Oracle и переживают
logout/restart клиента.
