# Gameplay Rules

## 1. Архитектурные правила
- Весь backend реализован на Oracle PL/SQL.
- Центральная точка бизнес-логики: `pkg_genetics_game`.
- Python является только GUI-клиентом.
- Python не рассчитывает генетику, мутации, задания, экономику, рейтинг и статистику.
- GUI получает данные через `SYS_REFCURSOR`, OUT-параметры и простые RETURN-типы.
- `dbms_output` не используется как источник данных для GUI.

## 2. Базовый игровой цикл
Игрок:
1. авторизуется;
2. выбирает/создаёт лабораторию;
3. работает с коллекцией существ;
4. проводит генетические эксперименты и мутации;
5. выполняет задания;
6. отслеживает историю экспериментов и показатели лаборатории.

## 3. Лаборатория на старте
`start_new_lab` сразу:
- создаёт лабораторию;
- назначает 3 `ACTIVE` задания;
- генерирует стартовую популяцию из 30 существ.

`generate_starting_creatures` идемпотентен (повторно 30 существ не дублирует).

## 4. Генетика и фенотип
- Генотип хранится в `genotypes` (по 2 аллели на ген).
- Фенотип рассчитывает backend (`get_phenotype`).
- `phenotype_summary` и cached phenotype-поля обновляются backend.

Семантика `dominance_type`:
- `FULL` — обычное доминирование;
- `INCOMPLETE` — при разных аллелях промежуточный признак;
- `CODOMINANT` — при разных аллелях отображаются оба признака.

## 5. Мутации и мутагены
- `show_mutation_shop` — доступные мутации.
- `buy_mutation` — покупка мутации для лаборатории.
- `apply_mutation` — направленное изменение по `mutation_rules`.
- `apply_mutagen` — экспериментальное воздействие, создающее новое существо.

Различие мутагенов:
- `CHEMICAL` — более контролируемый;
- `RADIATION` — более случайный, с большим риском.

## 6. Экономика (economy pass)
- `buy_mutation`:
  - уменьшает `wallet`;
  - увеличивает `lab_mutations.quantity`;
  - не меняет `rating`.
- `apply_mutation`:
  - применяет `mutations.rating_effect` к `labs.rating` через `greatest(0, ...)`;
  - затем может добавить награды через auto-complete задач.
- `apply_mutagen`:
  - `RADIATION`: `cost=50`, `rating_delta=-5`;
  - `CHEMICAL`: `cost=100`, `rating_delta=-2`;
  - изменения рейтинга также ограничены снизу `greatest(0, ...)`.

Важно: рейтинг после мутагена может в итоге вырасти, если auto-complete закроет задачу с `rating_reward`.

## 7. Задания
- Стартовые задания назначаются при создании лаборатории.
- Проверка условий задачи идёт через backend (`check_task`) по `task_markers`.
- Завершение задачи (`complete_task`) выполняет:
  - перевод в `COMPLETED`;
  - начисление `wallet/rating`;
  - защиту от повторного начисления.
- После завершения задач backend пополняет active-пул до целевого уровня (если есть неназначенные задачи).

## 8. Multiuser/session-bound правила
- Доступ к лаборатории привязан к активной backend-сессии.
- Одна и та же лаборатория не может быть одновременно открыта в двух ACTIVE sessions.
- `load_lab/switch_lab` проверяют owner и занятость лаборатории.
- Ошибки:
  - `-20072`: лаборатория уже открыта в другой активной сессии;
  - `-20073`: лаборатория не активна в текущей сессии.
- Gameplay API работают только для активной лаборатории текущей session context.

## 9. Локализация отображения
- Технические коды в БД сохраняются как есть.
- Пользовательское отображение русифицируется в display-layer GUI.
- Локализация display-layer не заменяет backend-правила и не переносит логику из PL/SQL.

## 10. Текущий тестовый baseline
- Backend smoke-tests `01..08` — зелёные (`Failed: 0`).
- Компиляция `pkg_genetics_game` успешна, `user_errors` пустой.

## 11. Аудит контента по ЛР1/ЛР2 и KB
Текущий каталог признаков достаточен для базового strict baseline:
- 6 видов существ;
- 4 универсальных признака;
- видоспецифичные признаки для `species_type 1..6`;
- по 2 аллеля на ген;
- `FULL`, `INCOMPLETE`, `CODOMINANT`;
- `mutation_rules` и `task_markers` покрывают универсальные признаки и все виды.

Игровые допущения:
- Технические коды генов/аллелей остаются в БД, русское отображение выполняет GUI display-layer.
- Не каждый вид имеет несколько уникальных видоспецифичных признаков, но универсальные признаки применяются ко всем существам.
- `linkage_group` уже поддержан backend-логикой; для более наглядной демонстрации можно расширить seed осмысленными связанными парами генов.

Отложенные треки:
- хранение точного типа мутагена и изменённого гена в истории экспериментов;
- поколение существа (`generation`) в коллекции;
- дополнительные признаки/аллели только после подтверждения KB-таблицы.
