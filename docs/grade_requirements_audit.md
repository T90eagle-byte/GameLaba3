## 5. Что можно честно говорить на пересдаче

Проект уверенно закрывает уровень 3:

- реализовано 6 видов вместо минимальных 5;
- есть признаки цвет/размер/крылья/питание;
- есть гены, аллели, генотипы, phenotype cache;
- есть скрещивание двух родителей и расчет вероятностей;
- есть задания на предъявление существа с нужными признаками;
- стартовая лаборатория генерирует 30 существ и active tasks.

Проект в основном закрывает уровень 4:

- есть неполное доминирование;
- есть кодоминирование как дополнительное усиление;
- есть сцепленные гены;
- есть directed mutations и случайные mutagens;
- RADIATION/CHEMICAL имеют стоимость, штраф рейтинга и риск;
- есть история экспериментов.

Что является инженерным расширением сверх уровня 4:

- `rating_events` как объяснимая история изменений рейтинга/кошелька;
- многопользовательские сессии и защита чужих лабораторий;
- справочники `ref_*` и строгие FK;
- smoke-tests `01..10` и воспроизводимый runner;
- package API, совместимый с ЛР2;
- Python-клиент без gameplay SQL и без переноса бизнес-логики.

Чего нет для уровня 5:

- нет настоящей экосистемы/вольера;
- нет смертности существ;
- нет совета по этике;
- нет автоматического закрытия лаборатории за этические нарушения;
- нет backend-правил баланса хищники/травоядные.

## 6. Риски для защиты

- Если преподаватель ждет буквальную “волко-собаку”, нужно объяснить адаптацию: проект не про одну породу, а про многовидовую “БиоСборку”; “заказы клиента” реализованы через задания и `task_markers`.
- Если спросят “где экосистема”, честный ответ: это roadmap уровня 5, текущая версия закрывает 3/4 и готовит признаки питания как базу.
- Если спросят “где совет по этике”, показать штрафы за мутагены и `rating_events`, но не утверждать, что совет уже реализован.
- Если спросят, почему Python не считает генетику, объяснить архитектурное решение: бизнес-логика вынесена в Oracle PL/SQL package, клиент только вызывает API и отображает данные.
- Если спросят про “3 случайных варианта потомства”, показать `calculate_punnett_probabilities` и создание потомка; признать, что отдельный backend cursor ровно на 3 preview-варианта не выделен.
- Если спросят про происхождение существа в задании, уточнить: текущие задания marker-based и проверяют признаки, не provenance.

## 7. Рекомендация

- Не добавлять сейчас требования на 5 перед пересдачей: это крупный DDL/backend/gameplay трек с высоким риском.
- Сосредоточиться на стабильной демонстрации уровней 3 и 4.
- Показывать `rating_events`, справочники, FK, multiuser sessions и runner `01..10` как сильные инженерные улучшения сверх базовых требований.

- Требования уровня 5 оставить как roadmap после web-клиента и отдельного проектирования ecosystem/ethics mechanics.
