# Project roadmap

## Этап 0. Аналитический каркас

Статус: выполнено.

Результаты:

- изучены ЛР1 и ЛР2;
- создана карта архитектуры;
- создана карта БД;
- описаны правила геймплея;
- создан стартовый каркас каталогов.

## Этап 1. Контракт базы данных

Цель: подготовить точную схему без реализации логики.

Задачи:

- утвердить `snake_case` имена таблиц и столбцов;
- решить вопросы по `linkage_group`, `species_type` и фенотипическим столбцам;
- описать PK, FK, уникальные ограничения и CHECK-ограничения;
- определить справочники для генов, аллелей, мутаций и заданий;
- подготовить будущий DDL-план.

Выход этапа:

- согласованная схема;
- готовность писать DDL на следующем шаге.

## Этап 2. PL/SQL package specification

Цель: зафиксировать внешний API Oracle для Python.

Задачи:

- создать спецификацию `pkg_genetics_game`;
- привести имена параметров к `snake_case`;
- определить типы OUT-параметров и `sys_refcursor`;
- разделить процедуры для `dbms_output` и процедуры для GUI;
- зафиксировать ошибки и ожидаемые коды результата.

Выход этапа:

- package specification без тела;
- документированный контракт для GUI.

## Этап 3. PL/SQL package body

Цель: реализовать бизнес-логику в Oracle.

Задачи:

- регистрация, вход, выход и сессии;
- создание и загрузка лабораторий;
- генерация стартовых существ;
- вычисление фенотипа;
- наследование независимых и сцепленных генов;
- скрещивание;
- мутации и мутагены;
- задания и награды;
- статистика лаборатории.

Выход этапа:

- рабочий `package body`;
- ручные PL/SQL-проверки основных сценариев.

## Этап 4. Данные и тестовые сценарии

Цель: наполнить игру минимально достаточными данными.

Задачи:

- подготовить набор генов и аллелей;
- подготовить 6 типов существ;
- подготовить мутации;
- подготовить задания и маркеры заданий;
- проверить стартовую генерацию 30 существ;
- проверить выполнение задания через генотип.

Выход этапа:

- воспроизводимый набор стартовых данных;
- тестовые сценарии для демонстрации.

## Этап 5. Python client layer

Цель: создать клиентский слой без GUI-логики.

Задачи:

- настроить подключение к Oracle;
- сделать адаптер вызовов `pkg_genetics_game`;
- реализовать чтение `sys_refcursor`;
- реализовать обработку ошибок Oracle;
- подготовить DTO/view models для GUI.

Ограничение:

- Python не считает генетику, задания, экономику и мутации.

## Этап 6. GUI

Цель: реализовать пользовательский интерфейс игры.

Окна и вкладки:

- вход и регистрация;
- выбор или создание лаборатории;
- обзор лаборатории;
- коллекция существ;
- карточка существа и генотип;
- скрещивание;
- задания;
- магазин мутаций;
- мутагенные эксперименты;
- история экспериментов.

Выход этапа:

- GUI, который управляет игрой через PL/SQL API.

## Этап 7. Интеграция и подготовка к GitLab

Цель: привести проект к сдаваемому виду.

Задачи:

- добавить README с инструкцией запуска;
- добавить `.gitignore`;
- проверить структуру каталогов;
- проверить, что PDF и markdown-документация лежат в `docs`;
- проверить, что нет секретов и паролей;
- подготовить демонстрационный сценарий;
- зафиксировать известные ограничения.

## Критерии готовности MVP

- пользователь может войти;
- пользователь может создать лабораторию;
- создаются стартовые существа;
- GUI показывает коллекцию и генотип;
- можно скрестить двух существ;
- потомок сохраняется в БД;
- можно купить и применить мутацию;
- можно выполнить хотя бы одно задание;
- статистика лаборатории обновляется через PL/SQL.
