# Web-клиент БиоСборки

Лёгкий Flask/Jinja интерфейс для проекта GameLR3 / БиоСборка. Клиент рассчитан на запуск на слабом учебном стенде: без React, Vue, Node.js и frontend-сборки.

## Назначение

Web-клиент нужен как переносимый браузерный интерфейс для защиты. Он показывает существ, задания, скрещивание, мутации, эволюционную линию и историю действий.

## Визуальная концепция

Интерфейс оформлен в мягкой биологической эстетике:

- природная зелёно-глиняная палитра;
- карточки существ с CSS-портретами;
- русские названия видов и признаков;
- бейджи фенотипа вместо сырых кодов;
- карточки генотипа вместо технической таблицы;
- timeline для эволюционной линии;
- визуальное разделение положительных и отрицательных изменений монет и рейтинга.

Визуализация является display-only слоем и не меняет игровые правила.

## Версионные портреты существ

Лаборатории `genetics_version = 1` продолжают использовать прежний SVG-портрет
на основе legacy-фенотипа. Для `genetics_version = 3` один общий renderer
строит inline SVG только по 18 каноническим морфологическим признакам из
`GENOTYPES`, полученным через package cursor. Он не использует archetype как
источник внешности: поэтому реальные потомки со значением `archetype_id = NULL`
отображаются так же корректно, как стартовые существа.

Для списка существ и карточек родителей `/crossbreed` web получает базовый
список и один lab-wide cursor морфологии, то есть выполняет не более двух
Oracle-вызовов независимо от числа существ. Детальная карточка читает свои 18
строк отдельным cursor. SVG несёт безопасные `data-*` признаки для тестов;
уникальные IDs градиента и тени строятся из UID карточки.

## Архитектурное правило

Бизнес-логика остаётся в Oracle PL/SQL package `pkg_genetics_game`:

- генетика рассчитывается в package;
- задания проверяются в package;
- скрещивание и предпросмотр потомства выполняются в package;
- мутации, мутагены, монеты, рейтинг и rating events ведутся в package;
- Flask только вызывает package API и отображает результат.

Единственный прямой SQL в web-коде — технический health-check `select 1 from dual`.

## Установка зависимостей

```powershell
.\.venv\Scripts\python.exe -m pip install -r web_client\requirements.txt
```

## Запуск

Для Windows-поставки используйте единый launcher
`deployment\\windows\\start_game.ps1`: он запускает Waitress и читает
параметры Oracle из `deployment\\windows\\.env`. Полная инструкция есть в
`deployment\\windows\\README.md`.

Для локальной разработки можно запустить Flask напрямую:

```powershell
.\.venv\Scripts\python.exe web_client\app.py
```

Адрес:

```text
http://127.0.0.1:8000
```

## Маршруты

- `/health` — полная readiness-проверка Oracle и игровой схемы; `200` означает готовность, `503` — web жив, но Oracle или схема требуют внимания.
- `/health/live` — liveness web-процесса без обращения к Oracle.
- `/register`, `/login`, `/logout` — регистрация, вход и выход.
- `/labs` — создание, открытие, переименование и удаление лаборатории. Занятая лаборатория не прерывает другие сессии: передачу доступа только к ней нужно подтвердить отдельно.
- `/dashboard` — обзор выбранной лаборатории с её актуальным названием и быстрый маршрут защиты.
- `/creatures`, `/creatures/<id>` — существа, фенотип и генотип.
- `/tasks` — задания, проверка и выполнение задания.
- `/crossbreed` — выбор родителей, 3 preview-варианта и создание потомка.
- `/mutations` — каталог мутаций, применение мутаций, RADIATION/CHEMICAL.
- `/experiments` — эволюционная линия через историю экспериментов.
- `/rating-events` — история изменений монет и рейтинга.

## Ручной smoke checklist

1. Открыть `/health`.
2. Зарегистрироваться и войти.
3. Создать или открыть лабораторию.
4. Открыть обзор.
5. Открыть список существ и карточку существа.
6. Открыть задания, проверить задание и выполнить его подходящим существом.
7. Открыть скрещивание, показать 3 варианта, создать потомка.
8. Открыть мутации, купить/применить мутацию, применить RADIATION или CHEMICAL.
9. Открыть эволюционную линию и историю.
10. Выйти.

## Автоматический smoke

```powershell
.\.venv\Scripts\python.exe web_client\smoke_test.py
```

Скрипт использует Flask test client и package-backed service wrappers. Он не использует gameplay SQL и создаёт тестового пользователя/лабораторию в настроенной Oracle DB.

## Readiness перед защитой

```powershell
.\.venv\Scripts\python.exe database\scripts\check_runtime_readiness.py
```

Команда завершается с кодом `0`, только если Oracle доступна, обязательные таблицы и seed-данные существуют, миграционные инварианты соблюдены, package spec/body имеют статус `VALID`, в `user_errors` нет ошибок package и присутствуют все вызовы API, используемые web-клиентом. Проверка demo-набора ЛР3 остаётся отдельной:

```powershell
.\.venv\Scripts\python.exe database\scripts\check_lr3_demo_data.py
```

Если `/health/live` отвечает, а `/health` или readiness-check возвращают `503`/ненулевой код, сначала проверьте `.env`, Oracle/Docker и `database\scripts\run_tests.py`. Для существующей схемы примените недостающие миграции из `database\migrations` при остановленном приложении, затем повторите readiness-check.

## Troubleshooting

- Oracle недоступен: проверьте Docker/service, host/port, service name или SID.
- Не настроен `.env`: проверьте `python_client/.env`.
- Лаборатория открыта в другой сессии: продолжите работу там либо раскройте «Восстановить доступ» у выбранной лаборатории и явно подтвердите передачу. Остальные лаборатории и сессии останутся активными.
- Нет выбранной лаборатории: откройте `/labs` и создайте/откройте лабораторию.
- Package invalid: запустите `database\scripts\run_tests.py` и проверьте `user_errors`.
- Недостаточно монет, несовместимые родители или недоступная мутация: это штатный ответ игровых правил, web должен показать flash-сообщение без traceback.
